## 关键设计决策

**1. 消息内容块在进入 messages 前统一转成普通 dict（`_block_to_dict`）。**
一石三鸟：messages 全程 JSON 可序列化（会话持久化直接 `json.dump`，零自定义序列化代码）；消除对 SDK 对象类型的依赖；测试的假响应和真响应走同一条路径。这叫"在边界处归一化数据"——数据一进门就转成自己的格式，内部所有代码都不用再操心它从哪来。

**2. 流式输出是可选增强，不是循环的重写。**
`run_turn(user_input, on_text=None)`：传了回调且 client 支持 `.stream` 才走流式，否则回退 `create`。核心循环逻辑一行没改——流式只是"同一个响应换一种到达方式"。测试用的假 client 没有 stream 方法，自动走旧路径，所有旧测试零修改。

**3. Ctrl+C 回滚到轮次检查点。**
中断发生在模型回复到一半时，messages 会停在"有用户输入、无 assistant 回复"的非法状态（下次请求角色不交替直接报错）。所以 `_run_one_turn` 记录轮次开始时的消息数，中断时 `del messages[checkpoint:]` 整轮丢弃。**状态回滚比状态修补简单可靠**。

**4. slash 命令全部收敛到 `handle_slash(command, agent) -> str`。**
一个纯函数风格的分发器，输入命令返回显示文本，不直接 print——测试直接断言返回值，不用捕获 stdout。

## 踩坑记录

`KeyboardInterrupt` 继承自 `BaseException` 而非 `Exception`——测试的假 client 里 `isinstance(r, Exception)` 判断漏掉了它。这个语言细节在生产代码里是**故意利用**的：`_execute_tool` 只捕 `Exception`（工具报错要喂回模型），Ctrl+C 属于 `BaseException` 会穿透到 CLI 层触发回滚——两层各接各的异常，Python 异常层级设计的意图就是如此。

## 验收结果

- ✅ `uv run pytest` 77 个全绿
- ✅ 流式输出：真实 API 下 92 个文本增量块（首块 2.8s，末块 4.3s），拼接结果与最终回复完全一致；spinner 随机状态词可见（如 "Percolating…"）
- ✅ 每个 slash 命令通过管道输入实测：/help、/cost、/mode yolo（真切换）、/model opus（真切到 deepseek-v4-pro）、未知命令提示
- ✅ 会话恢复：会话 A 记住暗号『海豚42』并保存 → 全新 agent --resume 语义加载 → 询问暗号回答正确
- ✅ Ctrl+C：单元测试模拟生成途中中断，messages 精确回滚到轮次前状态（真实终端按键场景无法脚本化，以单测 + 回滚逻辑审阅代替，如实记录）

## 遗留问题

- Live + Markdown 重渲染在超长回复时会闪烁；Claude Code 用了更精细的增量渲染。不修。
- 会话恢复不恢复权限白名单和 `_read_files`（只恢复 messages）；恢复后首次编辑会被要求重读文件——行为保守但安全，可接受。
