# M4：系统提示词 + 项目记忆

日期：2026-07-13

## 做了什么

给 agent 装上了"性格与操作手册"（system prompt），并复现 Claude Code 的 CLAUDE.md 项目记忆机制（我们的文件名叫 AGENT.md）。M1/M2 验收里两次撞到的"agent 不知道自己在哪"的问题，本里程碑正式解决。

新增/修改文件：
- `minicode/prompts.py`：`build_system_prompt()` 三层组装——静态部分（身份/风格/工具规范/安全，每段带设计意图注释）+ 环境区块（cwd/平台/日期/目录一级结构）+ AGENT.md 记忆（存在才注入）
- `minicode/agent.py`：会话开始时组装一次 system prompt，每次请求走 SDK 的 `system` 参数
- `tests/test_prompts.py`：5 个测试

## 关键设计决策

**1. system prompt 走 `system` 参数，不放进 messages。**
两个原因：一是语义正确——它是"配置"不是"对话"，模型对 system 区的指令服从度也高于普通消息；二是为 M6 埋下伏笔——将来 compaction 压缩的是 messages，system prompt 永远不会被压掉，agent 的"性格"和项目规则在长对话里也不丢失。

**2. 静态提示词按"设计意图"分段，注释写在代码里。**
四段各解决一类真实问题：身份段（不写会自居聊天助手、只建议不动手）、风格段（抑制编造，M2 的路径臆想就是反面教材）、工具选择段（工具 description 说"怎么用我"，这里说"什么场景选谁"，两层配合）、安全段（权限系统是硬约束，这里是软约束，让模型主动不越界而不是撞上守门人）。

**3. 环境区块用 `<env>` 标签包裹。**
模仿 Claude Code 的做法。XML 风格标签帮模型把"环境事实"和"行为指令"区分开，也方便在提示词里精确引用（"<env> 区块里已提供的信息……"）。

**4. AGENT.md 整体注入，不做解析。**
记忆文件的内容原样拼进 system prompt，前面加一句"以下规则必须遵守"。不解析、不分节、不做优先级——Claude Code 对 CLAUDE.md 也是这么做的（它多一个 import 语法，我们简化掉）。记忆文件的本质就是"用户预写的一段 system prompt"。

## 踩坑记录

**踩到了一个真正的提示词工程坑：指令之间会打架。** 第一版风格段写了"涉及文件/目录的问题，先用工具查证再回答"（本意是抑制编造），结果验收场景 2 里，模型面对"我在哪个目录"这个问题，宁可调 `bash: date && pwd` 也不用 system prompt 里现成的环境信息——它把"查证指令"的优先级理解得比"环境已注入"更高。严格说模型没错，是我们的两条指令组合出了歧义。

修复：风格段明确写出例外——"<env> 区块里已提供的信息可以直接引用，不需要再用工具确认"。重跑后 0 次工具调用直接答对。

教训（值得写在简历/面试里的那种）：**提示词不是一条条独立生效的，是作为整体被模型解读的。每加一条新指令，都要考虑它和已有指令的组合效果。** 这也是为什么 Claude Code 的 system prompt 迭代了几百个版本。

另外场景 2 的回复也以"收到老板"开头——AGENT.md 对同目录下的所有会话生效，这是预期行为，顺带验证了记忆的持久性。

## 验收结果

单元测试：`uv run pytest` 47 个全绿（新增 5 个 prompt 测试）。

真实 API 验收（DeepSeek，`scratchpad/m4_verify/`，内置 AGENT.md「回答永远以『收到老板』开头」）：
- ✅ AGENT.md 行为改变：「notes.txt 里写了什么」→ 回复以"收到老板"开头，内容正确
- ✅ 环境问答：「今天几号？我在哪个目录？」→ **0 次工具调用**，日期（2026-07-13）和完整目录路径全部答对
- ✅ 对比实验：同样的问题、人为清空 system prompt → 模型被迫调用 `bash: date && pwd`（1 次工具调用）才能回答。结论：环境注入把"每次都要花工具调用查的信息"变成了"免费"的——乘以每天几百次对话，这就是 Claude Code 把 env 区块做进 system prompt 的原因

## 遗留问题 / 给下个里程碑的备注

- 环境区块在会话开始时组装一次，长会话中日期跨天/目录结构变化不会刷新（Claude Code 也是会话级快照 + 部分动态刷新）。学习项目可接受，不修。
- AGENT.md 只查 cwd 一层，没有向上递归查找、也没有用户级全局记忆（`~/.minicode/AGENT.md`）——如果以后觉得需要，是十几行的扩展，先不做。
- 下一个 M5（搜索与精确编辑工具箱）：glob/grep/write_file + "编辑前必须先读"的强制约束。M4 的工具选择段到时候要补两行新工具的指引。
