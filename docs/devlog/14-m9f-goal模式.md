# M9f：goal 模式

日期：2026-07-13

## 做了什么

`minicode --goal "目标"` 无人值守模式：第一轮下达目标，之后每轮自动注入"继续"，直到模型输出 `<DONE>` 标记或达到 30 轮上限。实现是 `cli.py` 里 30 行的 `run_goal_mode()`。

## 关键设计

**goal 模式不是新循环，只是把"用户说继续"自动化了。** 复用 `run_turn`，核心代码零改动——这是整个项目分层正确性的又一次验证：交互模式（REPL / goal / 未来可能的 CI 模式）都只是"谁来产生下一条用户消息"的策略差异。

完成检测用显式标记 `<DONE>` 而非让模型自由发挥"我做完了"——结构化的完成信号比自然语言判断可靠（同一思想：能机制化的不靠语义猜测）。

## 验收

- ✅ 单测：mock 下循环至 DONE 停止、轮数上限生效
- ✅ 真实验收：goal="创建 greet.py + test_greet.py 并跑测试验证"，模型**一轮内**完成全部步骤（含 todo 清单管理、文件创建、pytest 验证）并输出 `<DONE>`，`run_goal_mode` 正确识别结束
