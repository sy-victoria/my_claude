# 远程 MCP OAuth 认证

## 做了什么

远程 MCP 连接在收到 HTTP 401 后，可按 MCP 2025-06-18 规范读取受保护资源元数据和授权服务器元数据，通过浏览器完成授权码 + PKCE，必要时动态注册公共客户端。配置 `oauth.client_id` 可使用预先注册的客户端。访问令牌和刷新令牌仅存在进程内存中，刷新请求始终带目标 MCP 的 `resource`。

## 设计取舍

- 只有用户级 `~/.minicode/mcp.json` 能配置远程服务，项目文件不能诱导本机打开外部授权页。
- 无头运行不等待浏览器；需要事先通过 `token_env` 提供令牌。
- 元数据地址必须与 MCP 服务同源，认证相关请求拒绝 HTTP 重定向，避免把令牌发往意外端点。
- 会话过期后重新握手，但不重放写工具。网络中断后无法确定工具是否执行过，必须先检查状态。
- 没有持久令牌库，重启进程后需要重新授权。这保持了项目不把凭据写入文件的约束，也意味着交互体验仍有改进空间。

## 验收

- 本机 HTTP 模拟服务器覆盖 401、元数据发现、动态注册、PKCE 校验、浏览器回调 state 校验、令牌刷新、`resource` 参数和无头模式拒绝。
- Windows 环境全量单元测试：117 通过、13 因平台条件跳过。
- 未接入真实第三方 OAuth 服务；跨服务兼容性尚需实测。
