# M9b：plan mode

日期：2026-07-13

## 做了什么

复现 Claude Code 的 plan mode：`/plan on` 后 agent 只能调研出方案，用户批准后 `/plan off` 再执行。实现完全复用 M7 引入的自定义工具集机制——`set_plan_mode` 把工具集物理切到只读子集 + system prompt 追加计划模式指令，退出时恢复。

新增/修改：`agent.py`（`set_plan_mode`、`PLAN_MODE_PROMPT`）、`cli.py`（`/plan on|off`）、`tests/test_plan_mode.py`（3 个测试）。

## 关键设计决策

**双保险：结构约束（工具集切换）+ 行为引导（提示词后缀）。**
只靠提示词说"不许修改"是不够的——验收实测证明了这一点（见下）。工具集物理不含写工具，模型无论如何"想"改都改不了；提示词后缀的作用是让它别反复撞墙，主动转向输出方案。两者缺一：只有结构约束，模型会反复尝试失败、体验差；只有提示词，模型可能直接绕过。

**幂等性细节**：重复 `/plan on` 不叠加提示词后缀（用类常量精确增删），单测覆盖。

## 验收结果（本项目最有说服力的一次安全验证）

- ✅ 87 个测试全绿
- ✅ plan mode 下要求"创建 fib.py"→ **模型先后两次尝试绕过**：先调 `write_file`（不在工具集，收到未知工具错误），又试图用 `bash` 的 heredoc（`cat > fib.py << EOF`）写文件（bash 也不在），全部失败后输出了规范的实施方案；`fib.py` 确实不存在
- ✅ `/plan off` 后说"方案批准了，执行吧"→ 正常创建并运行，输出正确

这次验收把「提示词约束会被模型绕过，结构约束不会」从理论变成了一手观测——模型收到的 system prompt 明明写着"禁止任何修改"，它还是尝试了两次。给面试官讲 agent 安全设计时，这是最好的案例。
