# 多后端与本地模型

## 做了什么

在原有 Anthropic 协议兼容路径之外，增加 OpenAI Chat Completions 兼容适配器。`--provider ollama --model <模型>` 默认连接本机 `127.0.0.1:11434/v1`，不要求 API Key；`--provider openai` 使用 `OPENAI_API_KEY`。agent 的会话和工具循环没有另起一套，而是在网络边界转换消息、工具声明、工具调用结果与 token 用量。

## 关键取舍

- 非 Anthropic 后端必须显式指定模型名，避免把 DeepSeek 默认模型误发到其他服务。
- provider 和 base_url 只能由用户设置或命令行决定，项目设置不能改变 API Key 的接收方。
- 带 API Key 的端点必须使用 HTTPS；无密钥的本机地址可使用 HTTP；认证请求不跟随重定向。
- 适配器先实现非流式 Chat Completions。模型的 function calling 能力由所选模型决定，不能假定所有本地模型都能稳定调用工具。

## 验收

- 本机模拟 OpenAI Chat Completions 服务验证完整的“模型工具调用 → agent 执行 → 工具结果回传 → 模型最终答复”链路及 token 统计。
- 未运行真实 Ollama 模型；本地 CPU 推理速度、内存占用和模型行为尚需按实际硬件验收。
