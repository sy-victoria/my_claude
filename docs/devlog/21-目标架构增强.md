# ForgeCode 目标架构增强

## 做了什么

在原有 Agent Loop 上补了统一工具结果预算、项目指令轮次刷新、OpenAI 兼容流式文本、只读文件工具并发、结构化子 Agent 结论、任务检查点与安全回滚，并提供固定 SWE-bench Lite 开发样本及离线故障注入框架。

## 关键设计

只并发内置只读文件工具；审批先在主线程完成，调用与结果按模型顺序通知。写入、shell、MCP 和子 Agent 仍顺序执行，避免扩大副作用竞争范围。Checkpoint 在模型响应与工具执行边界原子保存，崩溃后已完成的调用使用收据，状态不明的调用不重放。回滚逐文件比较写入后哈希；内容被用户或其他工具改过时留下冲突供人工处理。快照只覆盖 Agent 文件工具，不声称能撤销 shell 或远程服务动作。

## 验收与限制

本地 `pytest` 覆盖流式工具参数拼接、结果裁剪、项目记忆刷新、读并发写屏障、恢复收据、快照回滚、冲突保护、跨文件补丁及五个故障边界。真实 SWE-bench 解决率需另行运行模型和官方 Docker harness；目前的离线测试只验证评测接口和恢复机制。

## 跟着学

1. `minicode/agent.py`：模型循环、工具调度与 Checkpoint 接入点。
2. `minicode/harness.py`：持久收据、文件快照及哈希保护回滚。
3. `minicode/eval.py`：固定样本运行、补丁导出和指标对照。
