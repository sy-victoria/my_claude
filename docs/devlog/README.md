# 开发日志规范

每完成一个里程碑，在本目录新建 `NN-mX-简短名称.md`（NN 从 01 递增，如 `01-m0-项目骨架.md`、`02-m1-agent循环.md`），按以下模板写：

```markdown
# M<编号>：<里程碑名称>

日期：YYYY-MM-DD

## 做了什么
（一段话概述 + 新增/修改的文件列表）

## 关键设计决策
（逐条：做了什么决定、为什么、Claude Code 对应是怎么做的、我们简化了什么）

## 踩坑记录
（遇到的问题和解法；没有就写"无"，但通常都有）

## 验收结果
（把 roadmap 里该里程碑的验收标准逐条列出，注明 ✅/❌ 和实际验证方式/输出摘录）

## 跟着学
（给初学者的阅读指引：2~3 个建议阅读的代码位置 `文件:行号`，按什么顺序读，每处看什么）

## 遗留问题 / 给下个里程碑的备注
```

写作要求：
- 中文，写"为什么"多于写"是什么"
- 这是学习材料不是工作汇报，假设读者是第一次接触 agent 开发的人
- 验收结果必须来自实际运行，不许凭代码推断
